## 1. Purpose

This document evaluates publicly available cybersecurity datasets for their suitability in training and evaluating AutoSOC's detection components. It documents what each dataset contains, its known limitations, and how it will be used in the AutoSOC pipeline.

> **Important disclaimer:** No model training or evaluation has been performed. This document presents dataset properties based on published literature, dataset documentation, and community analysis. No results are claimed.

---

## 2. Evaluation Criteria

Each dataset is assessed against the following criteria:

| Criterion | Description |
|-----------|-------------|
| **Content** | What attack types, protocols, and traffic are represented |
| **Format** | Raw PCAP, pre-extracted features, logs, or labels-only |
| **Ground truth** | Quality and granularity of attack labels |
| **Class balance** | Ratio of benign to malicious traffic |
| **Time span** | Duration of capture; affects temporal generalization |
| **Traffic realism** | Whether traffic resembles real enterprise environments |
| **Availability** | Freely downloadable vs. gated |
| **Training suitability** | Fit for supervised/unsupervised ML model training |
| **Evaluation suitability** | Fit for benchmarking detection rules and models |
| **Known issues** | Documented problems cited in research literature |

### 3.1 CIC-IDS2017

**Full name:** Canadian Institute for Cybersecurity Intrusion Detection System Dataset 2017  
**Producer:** University of New Brunswick / Canadian Institute for Cybersecurity  
**Published:** 2017  
**DOI / URL:** [https://www.unb.ca/cic/datasets/ids-2017.html](https://www.unb.ca/cic/datasets/ids-2017.html)

#### 3.1.1 Contents

| Property | Detail |
|----------|--------|
| **Duration** | 5 days (Monday–Friday, July 3–7, 2017) |
| **Traffic volume** | ~2.8 million flows |
| **Benign profile** | Simulated realistic user activity (HTTP, HTTPS, FTP, SSH, email) from 25 machines |
| **Attack types** | Brute force (FTP, SSH, Web), DoS/DDoS (Slowloris, Hulk, GoldenEye, RUDY, Heartbleed), PortScan, Web attacks (SQL injection, XSS, Brute force), Infiltration, Botnet (ARES) |
| **Labels** | Per-flow labels: attack name or "BENIGN" |
| **Features provided** | 80 pre-extracted features via CICFlowMeter (byte counts, packet lengths, inter-arrival times, flags, etc.) |
| **PCAP files** | Available (large; ~50 GB total) |

#### 3.1.2 Likely Use in AutoSOC

- **Primary benchmark** for network-based classification models
- Evaluate Suricata rule detection rate on the PCAP files
- Train and evaluate flow-based anomaly detection (Isolation Forest, Autoencoder, XGBoost)
- Establish baseline detection metrics for Week 1 evaluation

#### 3.1.3 Strengths

- Large, widely used — enables comparison with published baselines
- Multiple attack categories across multiple days
- Both PCAP and pre-extracted CSV features available
- Attack types cover common threat categories relevant to enterprise SOC

#### 3.1.4 Limitations

- **Traffic realism concerns:** Background traffic is generated by a simulator (not real user workloads); attack traffic does not mix with benign in realistic ways — reported in multiple papers (Engelen et al., 2021; Tavallaee et al. critiques)
- **Label errors:** Community analysis has found mislabeled flows, particularly in the Infiltration day; some "BENIGN" flows contain attack artifacts
- **Feature leakage:** CICFlowMeter-extracted features include duration-based features that may not be available in real-time detection
- **Temporal bias:** Only 5 days of capture; no seasonal or long-term behavioral patterns
- **No endpoint data:** No logs, no process execution — network-only; cannot evaluate endpoint detection
- **Class imbalance:** Benign traffic heavily dominates; requires resampling for classification tasks
- **Aging:** 2017 attack techniques; some are dated relative to current threat landscape

#### 3.1.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| Flow classification (supervised) | ✅ Good | Large labeled dataset; standard benchmark |
| Anomaly detection (unsupervised) | ⚠️ Moderate | Class imbalance and realism issues complicate anomaly baselines |
| Temporal/sequence models | ❌ Limited | Per-flow features; no packet-level sequences in CSV form |
| Endpoint / process models | ❌ Not applicable | No endpoint telemetry |

#### 3.1.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| IDS rule coverage (Suricata) | ✅ Good | PCAP available for Suricata offline analysis |
| Zeek log evaluation | ✅ Good | PCAP can be processed through Zeek |
| ML model benchmarking | ✅ Good | Well-published baseline metrics for comparison |
| End-to-end pipeline test | ⚠️ Moderate | Realism concerns limit operational confidence |

### 3.2 CSE-CIC-IDS2018

**Full name:** CSE-CIC-IDS2018 on AWS  
**Producer:** Communications Security Establishment (CSE) + Canadian Institute for Cybersecurity  
**Published:** 2018  
**URL:** [https://www.unb.ca/cic/datasets/ids-2018.html](https://www.unb.ca/cic/datasets/ids-2018.html)

#### 3.2.1 Contents

| Property | Detail |
|----------|--------|
| **Duration** | 10 days (February 14–23, 2018) |
| **Traffic volume** | ~16 million flows |
| **Environment** | AWS-hosted victim network; 500 machines (50 desktops, routers, victim servers, firewalls) |
| **Attack types** | Brute force, Heartbleed, Botnet, DoS/DDoS, Web attacks, Infiltration, SQL injection, XSS |
| **Labels** | Per-flow labels |
| **Features** | 80 CICFlowMeter features (same as CIC-IDS2017) |
| **Network data** | PCAP + CSV per day per traffic type |

#### 3.2.2 Likely Use in AutoSOC

- Larger-scale companion to CIC-IDS2017 for broader evaluation
- Cloud environment context (AWS) relevant for modern SOC scenarios
- Cross-dataset generalization testing: train on 2017, evaluate on 2018

#### 3.2.3 Strengths

- Larger and more diverse than CIC-IDS2017
- Cloud environment adds relevance to modern infrastructure
- More machines and longer duration than 2017 dataset
- Same feature format as 2017 — easy joint evaluation

#### 3.2.4 Limitations

- **Inherits CIC-IDS2017 problems:** Same CICFlowMeter pipeline; same realism and label quality concerns
- **Accessibility issues:** AWS-hosted; downloading raw PCAP files is non-trivial and bandwidth-intensive (~200+ GB)
- **Label noise:** Similar mislabeling issues documented by the community (Engelen et al., 2021 covers both datasets)
- **Synthetic background traffic:** Same simulated user behavior concerns
- **No ground-truth packet-level labels:** Labels are at flow level only

#### 3.2.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| Flow classification (supervised) | ✅ Good | Larger and more diverse than 2017 |
| Anomaly detection | ⚠️ Moderate | Same issues as 2017 |
| Endpoint models | ❌ Not applicable | |

#### 3.2.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| Cross-dataset generalization | ✅ Good | Useful paired with CIC-IDS2017 |
| IDS rule coverage | ✅ Good | PCAP available |
| Operational realism | ⚠️ Moderate | Cloud environment; limited endpoint realism |

### 3.3 UNSW-NB15

**Full name:** UNSW Network Benchmark 2015  
**Producer:** University of New South Wales, Canberra (ADFA)  
**Published:** 2015 (paper); dataset updated 2016  
**URL:** [https://research.unsw.edu.au/projects/unsw-nb15-dataset](https://research.unsw.edu.au/projects/unsw-nb15-dataset)  
**Paper:** Moustafa & Slay (2015), "UNSW-NB15: a comprehensive data set for network intrusion detection systems"

#### 3.3.1 Contents

| Property | Detail |
|----------|--------|
| **Duration** | 31 hours across two capture sessions |
| **Traffic volume** | ~2.5 million records |
| **Attack types** | 9 categories: Fuzzers, Analysis, Backdoors, DoS, Exploits, Generic, Reconnaissance, Shellcode, Worms |
| **Labels** | Binary (attack / normal) + 9-class categorical |
| **Features** | 49 features extracted with Argus + Bro scripts; feature descriptions published |
| **PCAP** | Available (100 GB total; stored on separate server) |
| **Ground truth tool** | IXIA PerfectStorm used to generate attack traffic |

#### 3.3.2 Likely Use in AutoSOC

- Diverse 9-class evaluation for multi-class detection models
- Comparison benchmark with wide literature coverage
- Worm, backdoor, shellcode categories not well-represented in CIC datasets

#### 3.3.3 Strengths

- Nine distinct attack categories provide fine-grained evaluation
- Feature set documented in detail with field descriptions (unlike CIC datasets)
- Reasonably balanced attack category representation
- Wide adoption in literature — large baseline comparison pool
- Worm and shellcode categories not available in CIC-IDS2017/2018

#### 3.3.4 Limitations

- **2015 vintage:** Attack techniques are dated; modern evasion is not represented
- **Synthetic traffic:** IXIA traffic generator; similar realism concerns to CIC datasets
- **Feature extraction dependency:** Pre-extracted features rely on Argus and Bro (old Zeek) versions; reproducing from PCAP requires matching tool versions
- **Incomplete PCAP availability:** Full PCAP is large and not always easily accessible
- **9-class imbalance:** Some attack categories (Worms, Shellcode) have very few samples

#### 3.3.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| Multi-class classification | ✅ Good | 9-class granularity; well-published baselines |
| Binary classification | ✅ Good | Standard benchmark |
| Anomaly detection | ⚠️ Moderate | Synthetic traffic limits anomaly baseline quality |

#### 3.3.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| Multi-class detection | ✅ Good | Best dataset for fine-grained attack-type evaluation |
| Literature comparison | ✅ Excellent | Hundreds of published results to compare against |
| Modern threat realism | ❌ Poor | 2015 attacks; no modern TTPs |

### 3.4 TON_IoT

**Full name:** TON_IoT Telemetry Dataset  
**Producer:** University of New South Wales, Canberra  
**Published:** 2020  
**URL:** [https://research.unsw.edu.au/projects/toniot-datasets](https://research.unsw.edu.au/projects/toniot-datasets)  
**Paper:** Alsaedi et al. (2020), "TON_IoT Telemetry Dataset: A New Generation Dataset of IoT and IIoT for Data-driven Intrusion Detection Systems"

#### 3.4.1 Contents

| Property | Detail |
|----------|--------|
| **Environment** | Simulated IoT/IIoT environment with heterogeneous devices |
| **Data types** | Network traffic, OS logs (Windows/Linux), IoT device telemetry (weather, GPS, Modbus, ToN) |
| **Attack types** | Scanning, DoS, DDoS, Ransomware, Backdoor, XSS, SQL injection, Password attack, MitM |
| **Labels** | Binary + attack type |
| **Telemetry sources** | Network (PCAP + flow features) + OS process logs + IoT sensor data |
| **Features** | 44 network features; separate OS log features |

#### 3.4.2 Likely Use in AutoSOC

- **Multi-modal evaluation:** Network + OS log data available — closest to AutoSOC's multi-source vision
- IoT/OT context for future expansion
- OS log sub-dataset relevant to endpoint detection

#### 3.4.3 Strengths

- **Multi-modal:** Unique combination of network + operating system logs — aligns well with AutoSOC's multi-source normalization
- More modern attack types (ransomware, MitM)
- IoT context adds breadth beyond traditional enterprise datasets
- OS logs provide endpoint-adjacent visibility without requiring Sysmon

#### 3.4.4 Limitations

- **IoT focus may not generalize** to enterprise endpoint/server environments
- **Simulated environment:** IoT devices are simulated; traffic patterns may not reflect real deployments
- **OS log format** is not in standard Windows/Linux format — custom normalization required
- **Limited community adoption** relative to CIC and UNSW-NB15 — fewer published baselines
- **Ransomware and MitM samples** are limited in count

#### 3.4.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| Multi-modal detection | ✅ Good | Best available dataset for multi-source models |
| Network classification | ✅ Good | Covers modern attack types |
| OS log analysis | ⚠️ Moderate | Non-standard log format; needs custom parser |
| IoT-specific models | ✅ Good | Dedicated IoT/IIoT context |

#### 3.4.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| Multi-source pipeline | ✅ Good | Best dataset for testing multi-modal normalization |
| Modern attack coverage | ✅ Good | More recent TTPs than CIC/UNSW-NB15 |
| Enterprise SOC realism | ⚠️ Moderate | IoT focus limits enterprise generalizability |

### 3.5 Bot-IoT

**Full name:** Bot-IoT Dataset  
**Producer:** University of New South Wales, Canberra  
**Published:** 2018  
**URL:** [https://research.unsw.edu.au/projects/bot-iot-dataset](https://research.unsw.edu.au/projects/bot-iot-dataset)  
**Paper:** Koroniotis et al. (2019), "Towards the Development of Realistic Botnet Dataset in the IoT for Network Forensic Analytics"

#### 3.5.1 Contents

| Property | Detail |
|----------|--------|
| **Environment** | Simulated IoT network with real and virtual IoT devices |
| **Attack types** | DDoS (TCP/UDP/HTTP flood), DoS, Reconnaissance, Information theft (keylogging, data exfiltration), Service scan |
| **Traffic volume** | ~72 million records (highly imbalanced; attack-heavy) |
| **Labels** | Binary + detailed sub-category |
| **Features** | 46 pre-extracted features; statistical summary per packet |
| **PCAP** | Available |

#### 3.5.2 Likely Use in AutoSOC

- **DDoS and botnet C2 detection** evaluation
- IoT threat scenario complement to TON_IoT
- Testing detection of volumetric attacks and scanning behavior

#### 3.5.3 Strengths

- Very large dataset — good for statistical robustness
- Sub-categories provide granular botnet behavior labels
- Covers data exfiltration and reconnaissance patterns
- PCAP available for Zeek/Suricata re-analysis

#### 3.5.4 Limitations

- **Severe class imbalance:** Attack traffic vastly dominates (>95%); most classifiers achieve near-perfect accuracy trivially
- **IoT focus:** Limited relevance to traditional enterprise endpoint scenarios
- **2018 vintage:** Botnet techniques evolve rapidly; C2 patterns are dated
- **Limited protocol diversity:** Heavy focus on volumetric/flood attacks; limited application-layer sophistication
- **Artificial imbalance problem:** High accuracy numbers in literature are misleading due to imbalance; requires careful metric selection (F1, AUC-ROC)

#### 3.5.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| DDoS/flood detection | ✅ Good | Large volumetric attack samples |
| Botnet C2 detection | ⚠️ Moderate | Dated C2 patterns |
| General classification | ⚠️ Moderate | Severe imbalance requires careful handling |

#### 3.5.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| Volumetric attack detection | ✅ Good | Abundant DDoS samples |
| Balanced evaluation | ❌ Poor | Imbalance makes accuracy-based comparison unreliable |
| Enterprise SOC scenarios | ❌ Poor | IoT/botnet focus diverges from enterprise use cases |

### 3.6 DARPA OpTC (Operationally Transparent Cyber)

**Full name:** DARPA Operationally Transparent Cyber Dataset  
**Producer:** DARPA / Five Eyes collaborative  
**Published:** 2019–2020 (data collection period); publicly released 2020  
**URL:** [https://github.com/FiveDirections/OpTC-Data](https://github.com/FiveDirections/OpTC-Data)  
**Related:** DARPA Transparent Computing (TC) program

#### 3.6.1 Contents

| Property | Detail |
|----------|--------|
| **Environment** | Simulated enterprise network with Windows and Linux hosts |
| **Data types** | Host-level provenance data (process creation, file access, network connections, registry) |
| **Format** | JSON provenance graph events (CDM — Common Data Model format) |
| **Attack scenarios** | Red team exercises with real-world APT-style attacks over 3 days |
| **Scale** | ~1 billion+ events across ~1,000 hosts |
| **Labels** | Ground-truth malicious events labeled at entity and edge level in provenance graphs |
| **Attack actors** | Simulated nation-state / APT attacks (actual red team, not synthetic traffic generators) |

#### 3.6.2 Likely Use in AutoSOC

- **Provenance graph analysis** and lateral movement detection
- **APT-style kill chain** evaluation — multi-stage attack detection
- **Cross-host correlation** evaluation — attacks span multiple hosts
- Critical for evaluating graph-based ML approaches and LLM-based triage

#### 3.6.3 Strengths

- **Real red team attacks** (not simulated traffic generators) — significantly higher realism than CIC/UNSW
- **Provenance graph structure** — ideal for graph neural network approaches
- **Multi-stage APT scenarios** — lateral movement, persistence, exfiltration are all represented
- **Host + network + process** telemetry — richest multi-source dataset available
- **Enterprise-like environment** — Windows + Linux hosts in a domain environment
- **Ground truth at entity level** — malicious processes and connections individually labeled

#### 3.6.4 Limitations

- **Extreme scale** (~1 billion events) — requires distributed infrastructure to process; not suitable for single-machine experiments without significant subsampling
- **CDM format** — proprietary DARPA Common Data Model format requires custom parser; not directly compatible with Sysmon/Zeek/Suricata schemas
- **Limited attack diversity** — 3 days, specific red team scenarios; may not generalize to other attack types
- **Imbalance** — malicious events are a tiny fraction of benign provenance
- **Complexity** — graph-level analysis requires significant ML engineering; not suitable for simple classification baselines
- **Download and storage** — full dataset is hundreds of GBs compressed
- **Limited published baselines** — fewer papers than CIC/UNSW datasets; less community validation

#### 3.6.5 Training Suitability

| Model Type | Suitability | Notes |
|------------|-------------|-------|
| Graph neural networks | ✅ Excellent | Purpose-built provenance graph structure |
| APT / kill chain detection | ✅ Good | Real multi-stage attacks |
| Simple flow classification | ❌ Poor | Not designed for feature-based classification |
| LLM log reasoning | ✅ Good | Rich event sequences suitable for LLM context windows |

#### 3.6.6 Evaluation Suitability

| Evaluation Type | Suitability | Notes |
|----------------|-------------|-------|
| Advanced persistent threat detection | ✅ Excellent | Most realistic APT simulation available |
| Endpoint detection | ✅ Good | Host provenance data |
| Pipeline end-to-end | ⚠️ Moderate | CDM format requires custom normalization |
| Comparison with literature | ⚠️ Limited | Fewer published baselines than CIC/UNSW |

## 5. Proposed Dataset Usage Plan

### Phase 1 — Pipeline Testing (Day 1–7)

- **CIC-IDS2017** (Friday subset only, ~400MB PCAP): Run through Zeek → normalization → Suricata alert extraction
- Goal: verify the parsing and normalization pipeline produces valid events before any model training

### Phase 2 — Detection Rule Evaluation (Day 8–14)

- **CIC-IDS2017** + **UNSW-NB15**: Run compiled Sigma/Suricata rules; measure detection rate and false positive rate per attack category
- No ML models; rule-only evaluation

### Phase 3 — ML Model Training and Evaluation (Future)

- Train initial classifiers on **CIC-IDS2017** (well-published baselines)
- Evaluate on **CSE-CIC-IDS2018** for cross-dataset generalization
- Use **UNSW-NB15** for multi-class evaluation
- **TON_IoT** for multi-modal (network + OS log) experiments

### Phase 4 — Advanced Research (Future)

- **DARPA OpTC** for graph-based and LLM-driven triage experiments
- **Bot-IoT** for DDoS-specific model evaluation
- Cross-dataset experiments to assess generalization

## 7. Known Dataset Research Gaps

1. **No dataset combines Sysmon + Zeek + Suricata** from the same incident — multi-source normalization cannot be evaluated end-to-end without synthetic data or a live lab
2. **Modern evasion techniques** (HTTPS C2, DNS-over-HTTPS, living-off-the-land) are absent from all pre-2020 datasets
3. **LLM-relevant datasets** (natural language security narratives, analyst notes, SOC tickets) do not exist in public form — RAG evaluation will require synthetic data
4. **Realistic benign traffic** is a universal gap — all datasets use simulated benign profiles
5. **Labeled lateral movement** at the network level is extremely rare; DARPA OpTC is the only public dataset with real examples
